# Sprint 1 記事案

## 第一候補タイトル

個人開発でもスプリントを切ると何が見えるのか

## タイトル案

- 個人開発でもスプリントを切ると何が見えるのか
- 個人開発アプリ MyTimes v1 に向けて、1週間でどこまで作れたか
- Linear と GitHub で個人開発の1週間スプリントを振り返る
- MyTimes v1 開発ログ: Sprint 1 で PR 5本をマージした話
- Markdown 正本の分報アプリを作る: v1 Sprint 1 振り返り
- AI と進める個人開発: MyTimes Sprint 1 の実績と次の見通し

Qiita に投稿するなら、最初はプロダクト名よりも「個人開発でもスプリントを切ると何が見えるのか」のほうが入り口として読みやすい。
本文の中で MyTimes の紹介に入る構成にする。

## 記事の方向性

作ったもの紹介だけではなく、Linear / GitHub / Codex を使って1スプリントをどう進めたかに寄せる。

読み手に伝えたいことは以下。

- 個人開発でもスプリントを切ると、進捗と見積もりが数字で見える
- Linear の Cycle と GitHub PR を対応させると振り返りやすい
- 作った機能だけでなく、レビュー対応や UI 調整にどれくらい commit が増えるかも見える
- 次スプリントの見通しを、感覚ではなく実績から立てやすくなる

## 本文構成案

### 1. 作っているもの

MyTimes は Markdown ファイルを正本にした分報・メモアプリ。
Obsidian 的にローカル Markdown を扱いつつ、チャット風に投稿できる体験を目指している。

### 2. Sprint 1 の目的

- v1 公開範囲を決める
- Markdown 正本化の土台を作る
- GitHub Issue から Linear にチケット管理を集約する
- v1 公開までのスケジュールを決める
- Sprint 2 以降に進める issue を整理する

### 3. 実際にできたこと

- Linear: 16 issue 中 15 Done、1 Canceled
- GitHub: PR 5本マージ
- マージ対象の作業 commit: Sprint 1 期間内で 51 件
- ローカル全ブランチ上の Sprint 1 期間内作業 commit: 58 件
- ノート作成・リネーム・削除
- Markdown ファイル一覧のツリー表示
- 日次ノート自動作成
- 右クリックメニュー
- 設定画面拡張

### 4. 数字で見た振り返り

使える数字。

| 指標 | 実績 |
| --- | ---: |
| Linear Cycle 1 issue 数 | 16 |
| Done | 15 |
| Canceled | 1 |
| 通常の未完了残件 | 0 |
| GitHub マージ PR | 5 |
| PR 上の作業 commit | 52 |
| Sprint 1 期間内のマージ対象作業 commit | 51 |
| Sprint 1 期間内のローカル作業 commit | 58 |

日別 commit 数。

| 日付 | commit 数 |
| --- | ---: |
| 2026-06-01 | 2 |
| 2026-06-02 | 7 |
| 2026-06-03 | 2 |
| 2026-06-04 | 6 |
| 2026-06-05 | 12 |
| 2026-06-06 | 8 |
| 2026-06-07 | 21 |

書けそうな考察。

- 最終日に 21 commit あり、終盤に設定画面の UI 調整とレビュー対応が集中した
- 大きめの機能は PR 1本でも commit 数が増える
- 小さく issue を切ると Done 数は増えるが、UI 調整やレビュー対応は別途時間を使う
- PR 数だけより、commit 数と Done issue 数を合わせて見るほうが実態に近い

### 5. 分かったこと

- 個人開発でも Cycle を切ると、1週間のアウトプットを説明しやすい
- Linear issue と PR / commit を対応させると、次スプリントの見積もりがしやすい
- UI 実装は初回実装よりも、細かい調整とレビュー対応の commit が多くなりやすい
- Sprint 2 予定の一部を Sprint 1 で前倒しできたので、スケジュールには少し余裕が出た

### 6. 次にやること

Sprint 2 では以下を進める。

- MYT-31: 送信ショートカットと入力挙動を v1 仕様に合わせる
- MYT-40: メッセージ入力欄で Markdown を機能させる
- MYT-32: メッセージリアクションを実装する

進める順番は、MYT-31、MYT-40、MYT-32 がよさそう。
MYT-32 はリアクション状態の保存方式と Markdown 正本との関係を決める必要があるため、最後に置く。

## 書き出し案

個人開発で MyTimes という Markdown ベースの分報アプリを作っています。

v1 を 2026年6月中に公開するために、Linear で1週間単位のスプリントを切って進めることにしました。
この記事では、Sprint 1 で実際にどれくらい進んだのかを、Linear の issue 数、GitHub の PR 数、commit 数を使って振り返ります。
